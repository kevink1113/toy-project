# 오늘 일정·날씨 참고 카드

## 배경

`PRODUCT.md`는 출근 준비 대시보드가 지하철 출발 판단 외에도 오늘의 일정과 오늘의 날씨를 참고용으로 보여준다고 정의한다. 이 두 캐퍼빌리티는 `docs/specs/subway-departure-check`에서 의도적으로 범위 밖에 뒀던 것으로, 이 스펙에서 처음 완성한다.

`PRODUCT.md`가 정의한 범위 중 다음은 이번 스펙에 적용되는 제약이다.
- 일정과 날씨는 참고용으로만 표시하며, 지하철 출발 판단 로직에는 전혀 관여하지 않는다.

## 사용자에게 보이는 결과

- 사용자는 대시보드에서 오늘 일정(제목과 시작 시각)을 시간순으로 확인할 수 있다.
- 사용자는 대시보드에서 지금 날씨(기온·하늘 상태·강수 여부)와 함께, 오늘 남은 시간대별 날씨와 오늘의 최고·최저 기온을 확인할 수 있다.
- 두 정보는 화면을 켜놓은 동안 자동으로 최신 상태를 유지한다.

## 승인된 범위

- 캘린더 데이터 출처: 사용자가 Google 캘린더에서 발급한 ICS 주소를 서버가 주기적으로 가져와 파싱한다. OAuth는 쓰지 않는다. 파싱에는 `node-ical`을 쓴다(관련 근거는 `AGENTS.md`의 "외부 데이터: Google 캘린더 비공개 ICS 주소 파싱" 블록).
- 날씨 데이터 출처: OpenWeatherMap Current Weather API(현재 날씨)와 "5 day / 3 hour forecast" API(시간별 예보, 오늘 최고·최저 계산용). 종합운동장 인근 고정 좌표로 조회한다(관련 근거는 `AGENTS.md`의 "외부 API: OpenWeatherMap 현재 날씨" 블록).
- 갱신 주기: 캘린더·날씨(현재+예보) 모두 10분 주기로 자동 갱신한다(지하철의 30초보다 느슨한 주기).
- 화면 배치: 지하철 카드 아래에, 날씨(현재 기온·시간별 예보·최고/최저)와 다음 일정을 하나의 참고 카드로 묶어 보여준다. 참고용이라는 성격에 맞게 지하철 카드보다 덜 강조된 톤으로 표시한다.
- 캘린더 쓰기(생성·수정·삭제), 여러 캘린더 통합, 캘린더 선택 UI는 포함하지 않는다.
- 여러 날짜(내일 이후)의 예보는 다루지 않는다. 오늘 하루(현재+오늘 남은 시간대)만 다룬다.
- 시간별 예보는 오늘 남은 3시간 간격 예보 중 최대 4개까지 보여준다.

## 관찰 가능한 수용 기준

1. 일정 카드는 오늘(한국 표준시 자정~자정) 시작하는 일정을 시작 시각 순으로 나열한다. 반복 일정도 오늘에 해당하면 포함한다. 오늘 일정이 없으면 "오늘 일정 없음"을 보여준다.
2. 날씨 영역은 현재 기온, 하늘 상태(한글 설명), 강수 여부(비·눈이 오고 있는지)를 보여준다.
3. 날씨 영역은 오늘 남은 3시간 간격 예보를 최대 4개까지 시각·기온·하늘 상태와 함께 보여주고, 오늘의 최고·최저 기온도 함께 보여준다.
4. 모든 정보가 화면이 열려 있는 동안 10분 주기로 자동으로 다시 가져와 갱신된다.
5. 캘린더 또는 날씨(현재·예보 중 하나라도) 조회가 실패해도 해당 영역만 개별적으로 "가져올 수 없다"는 상태를 보여주며, 다른 영역(지하철 포함)의 동작에는 영향을 주지 않는다.
6. 일정·날씨 정보는 지하철 카드의 출발 판단 문구나 계산 결과를 전혀 바꾸지 않는다.

## 설정된 제약과 근거

- 캘린더와 날씨는 참고용으로만 존재하고 출발 판단에 관여하지 않는다. `PRODUCT.md`에서 이미 확정된 제품 경계이며, 이번 스펙에서 다시 판단하지 않는다.
- OAuth 대신 ICS 비공개 주소 방식을 택했다. 사용자가 실제 Google 캘린더 계정으로 OAuth 동의 화면·토큰 관리까지 구현하는 대신, 발급 즉시 쓸 수 있는 단순한 방식을 선택했다(비용 대비 얻는 것을 고려한 선택).
- 날씨는 OpenWeatherMap의 One Call API(3.0 이상)가 아니라 Current Weather API와 5 day/3 hour forecast API를 쓴다. One Call은 무료 사용에도 결제 카드 등록이 필요해, 등록 없이 되는 쪽을 택했다. forecast API도 같은 인증키로 카드 등록 없이 실제 호출에 성공한 것을 확인했다.
- 10분 갱신 주기는 OpenWeatherMap 무료 티어의 하루 1,000회 한도에 여유 있게 맞춘 것이다(현재 날씨·예보 두 엔드포인트를 10분마다 호출해도 하루 288회로 한도 안에 든다).

## 가정

- 종합운동장 인근 좌표는 위도 37.5111, 경도 127.0724로 고정한다. 실제 호출로 유효성을 확인했다.
- 오늘 일정은 최대 5개까지 표시하고, 그보다 많으면 "+N개"로 축약한다. 종일 일정은 시작 시각 대신 "종일"로 표기한다.
- 반복 일정(RRULE)이 오늘에 해당하는지 판단하는 것은 `node-ical`이 제공하는 전개 기능을 그대로 신뢰한다.
- 강수 여부는 OpenWeatherMap 응답의 날씨 코드(2xx 뇌우·3xx 이슬비·5xx 비·6xx 눈)나 `rain`/`snow` 필드 존재로 판단한다.
- 오늘의 최고·최저 기온은 지금부터 자정까지 남은 3시간 간격 예보들 중 최댓값·최솟값으로 계산한다. 오늘 중 이미 지나간 시간대(예: 새벽 기온)는 API가 과거 실측치를 주지 않으므로 반영되지 않는다.

## 범위 밖

- 일정 생성·수정·삭제, 여러 캘린더 통합, 캘린더 선택 화면 — 읽기 전용 단일 캘린더로 한정한다.
- 내일 이후의 예보, 시간별 예보 5개 이상 표시 — 오늘 남은 시간대 최대 4개까지만 다룬다.
- 캘린더·날씨가 지하철 출발 판단에 관여하는 것 — `PRODUCT.md`에서 이미 제외된 범위다.

## 미확정

- 없음. 남은 판단은 모두 위 가정으로 정리했다.

## 남은 리스크

- 사용자가 제공한 ICS 주소가 Google이 "공개 주소"로 발급한 경로(`/public/basic.ics`)라, URL을 아는 누구나 이 캘린더 내용을 볼 수 있다. 더 안전하게 하려면 Google 캘린더 설정에서 "비공개 주소" 경로로 다시 발급받아 바꿔야 하며, 이는 사용자가 판단할 몫이다.
- `node-ical`의 반복 일정 전개가 우리가 기대한 대로 "오늘 occurrence만" 정확히 걸러주는지는 실제 구현 중에 검증이 필요하다.
- OpenWeatherMap Current Weather API·forecast API의 무료 티어 한도나 응답 형식이 향후 바뀌면(예: One Call로 통합), 이 스펙의 데이터 출처 결정을 다시 검토해야 한다.
- 오늘 자정 근처(예: 밤 11시)에는 남은 3시간 예보가 1개 이하로 줄어, 최고·최저 기온이 사실상 의미 없어지거나 시간별 예보 영역이 거의 비어 보일 수 있다.
